# happ://cryptN/ — ключи расшифровки

Приложение расшифровывает happ-ссылки всех известных схем: `crypt`,
`crypt2`, `crypt3`, `crypt4`, `crypt5` (обе раскладки тела: legacy и
salted). Ключи этих схем **вшиты в код** (`python/runtime/happ_keys.py`) —
это те же ключи, что лежат внутри каждого дистрибутива клиента Happ
(экосистема: hpwnr, Happ-converter, nf776/happ-decryptor). Ничего
настраивать не нужно: happ-ссылка из sources.txt работает сразу.

## Пользовательские ключи (необязательно)

Файлы в этом каталоге **переопределяют/расширяют** встроенные ключи —
нужны только если Happ выпустит ссылку с новым ключом, которого ещё нет
в приложении (в логе будет причина: «неизвестный маркер ...»).

### `pkcs1_keys.json` — схемы crypt..crypt4

```json
[
  "<base64 DER приватного ключа для happ://crypt/...>",
  "<base64 DER для crypt2>",
  "<base64 DER для crypt3>",
  "<base64 DER для crypt4>"
]
```

Порядок строгий: индекс массива = версии ссылки (`crypt` → 0, … `crypt4` → 3).
Элементы замещают встроенные ключи по индексу.

### `crypt5_keys.json` — схема crypt5 (расширение)

```json
{
  "<8-символьный маркер>": "<base64 DER PKCS#8 приватного ключа>"
}
```

Маркер — первые 4 + последние 4 символа payload ссылки (после
block-pair-swap). Файл ДОБАВЛЯЕТ ключи к встроенному набору (36 маркеров).

## Безопасность

- Каталог `data/` игнорируется git; файлы не бандлятся в exe.
- Для собранного exe ключи кладутся рядом:
  `<путь к SubGenerator.exe>/data/happ_keys/*.json`.
- Встроенные ключи — константы интероперабельности публичного формата,
  не секрет пользователя.

## Зависимость

Расшифровка требует `pip install cryptography` (уже в requirements.txt).
Без библиотеки и без happ-источников проект работает как обычно;
happ-ссылка даст внятную ошибку в логе конвейера.
