# SubGenerator

Standalone-решение для сборки и проверки VPN-конфигов из подписок. Загружает
подписки, проверяет узлы на живучесть, тестирует обход блокировок и формирует
итоговую подписку (`subs.txt`), готовую для импорта в Karing, Hiddify, happ,
v2rayN.

**ПК-версия (Windows)**. Весь Python-код (конвейер, проверщики, рантайм ядер)
лежит в `python/`; запуск — напрямую из исходников (`generate.py`) или
сборкой в exe через PyInstaller (`build_release.bat`).

## Дисклеймер

Проект создан **исключительно в целях тестирования и научного интереса**:
изучение поведения сетевых протоколов, фильтрации трафика и устойчивости
конфигураций в контролируемой среде.

Автор не призывает и не содействует использованию инструмента в нарушение
законов или правил вашего региона. Используйте только в разрешённых целях
и только с подписками, на работу с которыми у вас есть право.

## Возможности

- GUI (customtkinter) и консольный режим (`--cli`).
- Поддержка vless, vmess, trojan, shadowsocks, hysteria, hy2.
- Парсинг подписок: plain text, base64, Clash YAML, JSON.
- Дедупликация конфигов (протокол, хост, порт, нормализованный URL).
- TCP/UDP-ping для быстрого отсева мёртвых узлов (до 256 потоков).
- **Автовыборка (v1.3)**: готовый конфиг-балансер из проверенных узлов —
  Xray `leastLoad` + `burstObservatory` (функциональная проба t.me) и
  sing-box `urltest` для hy2. Ядро само держит лучший узел.
- **Базовый замер сети (v1.3, v1.3.1, v1.3.2)**: перед тестом спидтест по белым
  для РФ сервисам (Яндекс.Интернетометр → tele2 → движок «проверки
  скорости» Билайна speedtest.ru → OVH; Cloudflare убран — на мобильных
  РФ не белый), пороги отбраковки адаптируются под реальную
  скорость (мобильная сеть 46/5 Мбит больше не бракует рабочие узлы).
  Кэп быстрого канала (v1.3.2): замер ≥ 100 Мбит/с НЕ слушается —
  используются пороги из UI (обычные VPN-конфиги 100+ Мбит всё равно
  не выдают, автозамер существует для мобильных сетей).
- **Таймауты этапов привязаны к таймауту UI (v1.3)**: выводятся
  пропорционально с нижними порогами — короткий таймаут не убивает
  живые медленные узлы.
- Проверка Telegram, ChatGPT, Instagram, скорости download/upload.
- DPI-проверки: DPI (+ Zapret-suite внутри), DPI-active, Resilience.
- ИИ-гео слепок (обязательный этап): страна exit-IP глазами
  Gemini/OpenAI (CF trace `loc=`) — источник флага в подписке; опция
  strict исключает узлы со слепком РФ.
- Telegram-медиа фильтр (обязательный): каждый узел реально качает
  видео из Telegram (t.me/s/, порог адаптируется под сеть).
- Игнорирование системного hosts-файла во всех проверках.
- Диагностика сети: UDP DNS, DoH, HTTPS, заблокированные цели
  (ChatGPT/Instagram/Telegram API) + **спидтест-прогон по белым
  сервисам** (v1.3.2: download/upload каскадом Интернетометра) —
  единая реализация для GUI и конвейера.
- Перепроверка с любого из 9 этапов (по сохранённому кешу).
- Сохранение настроек между запусками.

## Установка и запуск

### Из исходников

Требования: Python 3.12+, Windows 10/11 64-bit, права администратора
(управление процессами xray/sing-box), 16+ ГБ RAM.

```bat
pip install pyinstaller customtkinter darkdetect
python generate.py                       :: GUI
python generate.py --cli --help          :: консольный конвейер
```

### Сборка exe

```bat
build_release.bat
```

Результат в `build\`:
- `SubGenerator.exe` — GUI (запрашивает права админа автоматически);
- `SubGenerator-CLI.exe` — консольный режим (запрашивает права админа);
- `run_sub_generator.bat` / `.ps1` — one-click прогон с прогресс-баром;
- `sources.txt` — список подписок (редактируется в UI).

### Обновление ядер

Ядра `bin/xray.exe` и `bin/sing-box.exe` уже в репозитории. Обновление
до свежих релизов Xray-core / sing-box:

```bat
python scripts\download_cores.py                    :: последние релизы
python scripts\download_cores.py 26.3.27 1.13.16    :: конкретные версии
```

## Использование

### 1. Подписки

На странице «Подписки» добавьте URL подписок. Поддерживаются прямые
ссылки на `.txt`, `.yaml`, `.json`, base64, Clash YAML (`proxies:`),
локальный файл («Свой файл конфигов»).

### 2. Тестирование

Основные параметры (по умолчанию → смысл):

| Параметр | По умолчанию | Описание |
|---|---|---|
| Потоков | 32 | Параллельных проверок |
| Таймаут | 15 сек | База: от него ПРОПОРЦИОНАЛЬНО выводятся таймауты всех этапов |
| Макс. пинг | 1500 мс | Отсев по задержке |
| Мин. скорость | 3000 КБ/с | Порог скорости; при замере < 100 Мбит — смягчается до 60% от замера |
| Автовыборка | выкл | Готовый конфиг-балансер из рабочих узлов |

Перед проверкой (полный прогон со стресс-тестом) делается **базовый замер
сети** по белым для РФ сервисам: download/upload вашей сети мерится напрямую,
без прокси (Яндекс.Интернетометр, при недоступности — tele2, затем движок
«проверки скорости» Билайна speedtest.ru, последним — OVH), и пороги
отбраковки автоматически ставятся чуть ниже среднего от
замера — чтобы мобильная сеть с низкой отдачей (например, 46 Мбит/с
загрузка при 5 Мбит/с выгрузке) не браковала рабочие конфиги, которые
физически не могут показать больше, чем даёт канал. **Кэп быстрого
канала (v1.3.2)**: если замер ≥ 100 Мбит/с (проводной интернет),
автопорог замер НЕ слушает — используются значения из UI как есть
(3000 КБ/с — нормальный порог для классических VPN-конфигов).
Замер виден в отчёте
(`report.json` → `baseline`) и в `data/baseline_last.json`.

Этапы конвейера (последовательность, v8.2):

0. **baseline** — замер сети + адаптация порогов (v1.3, при стресс-тесте);
1. **ping** — TCP/UDP-отсев мёртвых портов;
2. **initial** — TCP+HTTP HEAD доступность;
3. **telegram_pro** — MTProto connect/auth + upload (главный критерий);
4. **dpi** — DPI (+ Zapret-suite, один core-процесс на узел);
5. **dpi_active** — SNI-варианты/фрагментация/ECH/TLS 1.2-1.3;
6. **ai_geo** — ИИ-гео слепок (CF trace `loc=`);
7. **route** — трассировка маршрута;
8. **resilience** — живучесть в условиях блокировок;
9. **recheck** — финальный спидтест (+ медиа-фильтр t.me/s/).

Таймауты этапов выводятся из базового таймаута: `initial` = 0.5×,
`telegram` = 0.6× (+ RTT-адаптация), `dpi` = 0.75× (не ниже значения из
`checker_thresholds.json`), `dpi-active` = 0.5×, `ai`/`route`/`resilience`
= 0.4×, `recheck` = большее окно (≥ 8с). Все — с нижними порогами.

### 3. Перепроверка

Страница «Перепроверка»: запускает проверку с выбранного этапа по
сохранённым рабочим конфигам из `data/.runtime_cache/` — без пинга и
стресс-теста.

### 4. Диагностика

Страница «Диагностика»: UDP DNS (порт 53), DoH, HTTPS connectivity,
прямая доступность ChatGPT/Instagram/Telegram API + таблица маршрутов —
видно, на каком этапе отваливается соединение. Использует ту же
реализацию, что и preflight конвейера (`checkers/net_diagnostic.py`).

С v1.3.2 в конце диагностики выполняется **спидтест-прогон**: download
и upload по тому же каскаду белых сервисов, что и в базовом замере
конвейера (Яндекс.Интернетометр → tele2 → speedtest.ru/Билайн → OVH).
Если замер ≥ 100 Мбит/с, выводится пометка, что автопорог конвейера
такой замер не слушает (используется порог из UI).

### 5. Результаты

`subs.txt` (base64-подписка) и `working.txt` (конфиги построчно) — в корне,
рядом с exe; `data/report.json` (полный отчёт с цифрами по этапам,
сетевым профилем и базовым замером). При включённой автовыборке —
дополнительно `data/autoselect_xray.json` и
`data/autoselect_singbox.json` (готовые конфиги: импортируются в
клиент целиком, ядро само выбирает лучший узел, проба — t.me).
На «Главной» — кнопка «Поделиться результатом».

## CLI

```bat
SubGenerator-CLI.exe --workers 32 --timeout 15 --dpi-check --dpi-siberian
```

| Параметр | Описание |
|---|---|
| `--workers N` | Потоков (32 по умолчанию) |
| `--timeout N` | База таймаутов: от неё выводятся таймауты всех этапов |
| `--autoselect` | Автовыборка: конфиг-балансер из рабочих узлов (v1.3) |
| `--dpi-check` | DPI ЦЕЛИКОМ: alive + tcp 16-20 + siberian + CIDR + Zapret-suite |
| `--dpi-active` | Активная DPI-проверка протокола (+ `--dpi-active-timeout`) |
| `--ai-strict` | ИИ-гео: исключить узлы со слепком РФ |
| `--ai-timeout N` | Таймаут ИИ-гео запроса, сек (по умолчанию 0.4× таймаута) |
| `--custom-file PATH` | Свой файл конфигов вместо подписок |
| `--no-stress` | Без спидтеста (базовый замер и пороги скорости пропускаются) |
| `--start-stage STAGE` | Перепроверка с любого из 9 этапов |

Полный список: `SubGenerator-CLI.exe --help`.

### v1.3.2 (2026-09-04) — кэп 100 Мбит, sources.txt в корне, спидтест в диагностике

  отмечено (`ignored: fast_channel`).
- **sources.txt вернулся в корень репозитория** (был в `data/`):
  пользовательский список подписок — единственный и лежит рядом с

  ТОЛЬКО рантайм-артефакты (логи, кеш, отчёты, settings,
  baseline_last) и игнорируется git целиком. Дубль
  `build\data\sources.txt` при сборке убран; спеки PyInstaller кладут

- **Диагностика сети: спидтест-прогон** (страница «Диагностика»):
  после обычных проверок выполняется download/upload по каскаду белых
  сервисов (тот же движок, что и базовый замер конвейера —
  Яндекс.Интернетометр → tele2 → speedtest.ru/Билайн → OVH);

### v1.3.1 (2026-09-04) — базовый замер: Cloudflare → белые RU-сервисы

- **Cloudflare speedtest (`speed.cloudflare.com/__down`, `/__up`) полностью
  выпилен из базового замера**: на мобильных сетях РФ он не входит в белые
  списки и регулярно режется/деградирует — замер падал или занижался,
  из-за чего адаптация порогов шла от неверных чисел.
- **Download-каскад** теперь: Яндекс.Интернетометр (CDN `…svc.cdn.yandex.net`,
  `/probes/50mb`; при смене бакета адрес добывается со страницы
  `yandex.ru/internet`) → `speedtest.tele2.net` → **speedtest.ru** — QMS-движок,
  тот же, что у страницы «проверки скорости» Билайна
  (`beelineru.ru/proverka-skorosti`: `nearest_servers` → `gentoken` →
  `download.php` на серверах РФ-провайдеров) → OVH (международный
  fallback).
- **Upload-каскад**: приёмник выгрузки Интернетометра (`GET
  internetometr.download.cdn.yandex.net/uploadhost` → POST на edge-ноду
  CDN Яндекса; приёмник проверяется на принадлежность хостам Яндекса)
  → `upload.php` QMS-движка Билайна.
- Стресс-проба узлов (через SOCKS-туннель) не менялась — там трафик
  выходит из узла за рубежом, и NDT7/CF/OVH/tele2 работают корректно.
